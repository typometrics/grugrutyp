# Audit, 2026-09-02

Four independent read-only reviews of grugrutyp, each from a different chair —
syntactician, typologist, software engineer, security reviewer — plus a synthesis.
Every claim below was made against the code, the configuration, or the **live cache and
database** (several findings are measured, not read). Nothing was modified during the
audit. File references are repo-relative; line numbers are as of commit `fd5ceee`.

## Executive summary

The house threat model — *a wrong count does not look wrong, it looks like a
typological finding* — is taken more seriously here than in most published pipelines,
and it shows: parameterised Cypher everywhere, a differential oracle against grewpy,
Wilson intervals with a three-trigger escalation, validated LLM output, rebuild guards,
same-commit documentation. All four reviewers independently rated the core engine
sound. The weaknesses cluster in four places, in decreasing urgency:

1. **Numbers being served wrong today** (§1): the `mean-distance-abs` preset includes
   root pseudo-edges while its own note claims the opposite; "mean sentence length" and
   "mean tree height" are length-weighted means mislabelled as means (a {5, 45} corpus
   reports 40.4, not 25); the UD presets and search examples drift off the project's own
   `1=` convention, worst in "Verbs without a subject", which counts every passive as
   subjectless; the flagship preset's caption inverts its own reading.
2. **What a "language" point aggregates over** (§2): Chinese counts the same 5,000
   sentences twice (GSD + GSDSimp), Japanese counts every sentence twice under two
   tokenization standards; "French" merges treebanks spanning 19–39% on a real measure
   into a point with a ±0.45pt interval; "Latin" hides a 15-point diachronic split; and
   the Wilson interval on summed counts understates the real uncertainty by an order of
   magnitude for heterogeneous languages. Plus curation errors a reviewer would catch on
   sight (Macedonian filed as Hellenic; Vietnamese under Sino-Austronesian; sign
   languages as Romance/Germanic).
3. **Operational fragility** (§3): no backup exists of anything irreplaceable —
   `users.sqlite` is one `rm` away from losing every account; the service is absent from
   the box's own watchdog and `/health` answers ok unconditionally; dependencies are
   unpinned; the cache key has two more blind spots of the kind that caused the
   2026-09-02 poisoning.
4. **Attack surface** (§4): the most expensive operation on the box is unauthenticated
   and unmetered — an anonymous loop of exact-mode `/measure` requests pins the shared
   disks and takes the legacy site down with it; query text of unlimited size reaches a
   super-linear parser; the API runs as root with no sandboxing.

None of the four found: injection paths, XSS, IDOR, broken auth, or a divergence in the
counting semantics of `with`/`without`/injectivity. The consolidated action plan is at
the end; the twelve quick wins in it are each under an hour.

## 1. The syntactician's report

### Strengths

- **The counting semantics are right where it matters most.** `with` compiles to
  `EXISTS` (not inlined MATCHes), `combine()` rejects `pattern` blocks and free
  identifiers in the response, and injectivity guards span `with`/`without` boundaries —
  so `0 ≤ #(S∧Q) ≤ #(S)` actually holds (`backend/grugrutyp/translate/cypher.py:602-642`).
  This is precisely where the Deworetzki & Ljunglöf scheme over-counts, and the docs say
  so honestly.
- **Feature-absence semantics match Grew throughout**: `<>` carries an `IS NOT NULL`
  guard, `without` pure filters get `coalesce(…, false)`, undefined values cluster as
  their own group — all the null-propagation traps a Cypher translation usually gets
  wrong are handled (cypher.py:143-146, 392-407).
- **Virtual root `__0__` is materialised and count-parity was measured**, not assumed
  (271,092 vs 256,739 on GUM recorded in three places), and the `skipFuncs=['root']`
  mismatch with the old site was caught, documented as a correction, and encoded into
  presets via explicit exclusions.
- **The `1=/2=/deep` label decomposition is done identically in both schemes** —
  matching Grew's edge-label-as-feature-structure model — and the string-vs-integer trap
  on the numeric counters was caught, fixed and regression-tested (`docs/menzerath.md`,
  `NUMERIC_NODE_PROPS`).
- **The differential harness is real infrastructure** (43 constructs × 3 typologically
  spread treebanks, sugar desugared for the oracle) and the project treats a wrong count
  as a bug that "looks like a typological finding" — the right threat model.

### Weak points

**Presets producing wrong numbers today**

1. **`mean-distance-abs` includes root pseudo-dependencies while its note claims the
   opposite.** `backend/grugrutyp/presets.py:260` — scope is `pattern { GOV -> DEP }`
   with *no* `without { GOV [form="__0__"] }`, yet line 265 attaches `BROAD_SCOPE_NOTE`
   ("The scope excludes the virtual root node `__0__` explicitly"). Every sentence
   contributes `|delta(__0__, root)|` = the root word's linear position. Failure: mean
   dependency length is inflated by an artifact that is *itself correlated with word
   order* (verb-initial vs verb-final roots sit at different positions), so a DLM
   comparison across languages is confounded, and the number is not comparable to the
   old `f-dist-abs` (root excluded there).
2. **"Mean sentence length" and "Mean tree height" are length-weighted means,
   mislabelled.** presets.py:270-297 — scope `pattern { X }` weights each sentence by
   `n_tokens + 1` (the `+1` is `__0__`, unmentioned even in the note). The value is
   Σ L(L+1)/Σ(L+1), not E[L]; for lengths {5, 45} that is 40.4 vs a true mean of 25.
   Failure: a syntactician cites "mean sentence length" from the axis and misreports it
   by tens of percent, worst in exactly the corpora (spoken, mixed-register) where
   length variance is high. `pattern { X [form="__0__"] }` would give one matching per
   sentence and the true mean for free.
3. **UD `adposition-prepositional` drops the mandated `1=` form.** presets.py:203 uses
   `N -[case]-> A` (exact label), against the project's own convention. `case:loc` in UD
   Chinese-GSD marks the *localizers* — the postpositions — so excluding subtypes
   deletes exactly the postpositional half and Chinese reads as near-100% prepositional.
   Same inconsistency across the search-tab examples:
   `frontend/src/views/SearchView.vue:396,399,413,459,465,468` use plain `-[obj]->`,
   `-[nsubj]->`, `-[amod]->`, `-[conj]->` in UD while the SUD twins use `1=`. Worst
   instance: "Verbs without a subject" (SearchView.vue:400-402) — UD
   `without { V -[nsubj]-> S }` counts every passive with `nsubj:pass` and every
   `nsubj:outer` clause as subjectless, inflating apparent pro-drop.
4. **`subj-obj-order` measures different clause sets in the two schemes under one
   caption.** presets.py:186-192 requires subj and obj on the *same* governor; in SUD
   the subject attaches to the finite auxiliary and the object to the lexical verb, so
   all periphrastic clauses fall out of the SUD scope while staying in the UD one. The
   scheme toggle carries a preset to its "twin" (`frontend/src/views/PlotView.vue:1584-1593`)
   with no note; a user flipping schemes attributes the jump to the language, not to a
   denominator change.
5. **Caption error on the flagship preset.** presets.py:88-92: "SVO-ish languages sit
   high on subj, verb-final ones low" — head-initiality of subj is the share of
   *post*-verbal subjects, so SVO languages sit **low** too (2-10%); verb-*initial*
   languages sit high. The About text gets it right ("most languages sit far left",
   App.vue:166); the preset description contradicts it.
6. **Punctuation contamination in the Menzerath counters.**
   `backend/grugrutyp/conllu.py:226-267` — `n_children`/`subtree_size` count `punct`
   (which attaches to the clause head in both schemes). "Mean dependents per verb"
   (presets.py:324) therefore partly measures treebank punctuation density; constituent
   sizes include commas. No note anywhere.
7. **`projectivity` denominator includes root edges** (presets.py:221) — reweights
   sentences by n+1 and counts a non-word-order edge, inconsistent with the sibling
   presets' word-to-word convention. Minor, but the only broad-scope preset without the
   exclusion or a note.

**Translator: silent divergences**

8. **Undeclared identifiers in feature comparisons silently bind fresh unconstrained
   nodes** — cypher.py:253-260 (`ensure`) plus 302-321. `X.lemma = lexicon.verbs`
   translates to a join against a new `Word` node named `lexicon` (verified), although
   `docs/grew-to-cypher.md:161` (§7 row 8) claims lexicons are "rejected at validation
   with a clear message" — they are not. Failure scenario: a case typo —
   `pattern { V -[1=subj]-> S; S.Number = v.Number }` — counts "some word in the
   sentence agrees in number", a wildly inflated agreement rate that looks like a
   finding. The binding discipline exists only on the response side (`combine()`), not
   inside the scope.
9. **Silent zeros from label lookalikes.** `-[E:nsubj]->` (enhanced-style) parses as
   `deprel = "E:nsubj"` → 0 everywhere; a singleton `-[1=*]->` parses via
   `edge_feature_single` as literal `rel_1 = "*"` → 0 (both verified;
   grammar.lark:60,119). The dead-axis banner (PlotView.vue:305) catches these only when
   zero *everywhere*, and only in plot mode, not search.
10. **Edge pseudo-features misparse instead of being rejected.** `e.length = 3`,
    `e.label = "subj"`, `X << e` have no grammar entry; they parse as *node* clauses and
    either re-declare the edge variable as a `:Word` (Neo4j type error at run time,
    surfaced as a cryptic per-treebank error) or, with an otherwise-unbound `e`,
    silently count node pairs. Loud constructs that fail well: `e1 >< e2`,
    `pattern {…} | {…}`, `-[!deep]->` alone, `is_forest`/`is_cyclic`, `meta.*` beyond
    sent_id/text; lexicon *syntax* is not — see 8.
11. **Regex divergence is only half-closed.** §7 row 2 closes *anchoring* but says
    nothing about dialect: Grew's `re"…"` is POSIX ERE, Cypher's `=~` is Java.
    `re"[[:upper:]].*"` matches uppercase-initial strings in Grew and a literal
    character class in Java — silently different matches, no error.
12. **MWT claim in §7 row 10 is optimistic.** "MWTs are separate `:Mwt` nodes, same as
    Grew" — Grew does not build MWT nodes; it exposes `textform`/`wordform` features on
    words. Those features are not imported, so a grew-match query using them returns
    silent zeros here despite the "a query copied from grew-match must give the same
    number" contract (neo4j-encoding.md §2 dev. 4).

**Oracle coverage**

13. **The UD half of the tool is never differentially tested.**
    `tests/conftest.py:50-64` pins `grewpy.set_config("sud")`; all three treebanks in
    `tests/test_differential.py:23` are SUD. Everything the docs assert about UD —
    `-[nsubj]->` exact vs `1=nsubj` subsuming under grew's `ud` config, decomposition of
    `nsubj:pass`/`acl:relcl` — is unverified against the oracle. Also uncovered: meta
    clauses, `e1.label = e2.label`, PCRE `/…/i`, `is_tree`, aggregate/cluster modes, and
    any order/distance clause that can bind `__0__` (`pattern { X; Y; X < Y }` counts
    the (`__0__`, word₁) pair per sentence here; whether Grew orders its virtual node
    identically is exactly the kind of thing this suite exists to check).

**The `1=` convention**

14. **`nl2grew.py:115` overclaims.** "the 1= form subsumes subtypes (nsubj:pass,
    nsubj:outer, aux:caus…), which is almost always what a typological measure means."
    Counter-cases the prompt never warns about: `nsubj:outer`'s governor is the *inner*
    predicate head, so it pairs an outer subject with the wrong clause in same-governor
    patterns; `1=obl` folds passive agents (`obl:agent`) into "obliques"; `1=aux` folds
    causative markers (`aux:caus`); `1=acl` folds relative clauses into all adnominal
    clauses. Failure: an LLM-drafted "position of obliques" measure diverges most in
    passive-heavy languages, with a caption that says nothing.

**Cross-scheme commensurability**

15. Within one plot both axes share one `scheme` ref, and a scheme flip greys the plot
    behind a "settings changed" banner (PlotView.vue:316-323) — good. The residual traps
    are (4) above, and PlotView.vue:1588-1589's stated assumption that a hand-written
    query carried across schemes "fail[s] visibly": a SUD-shaped
    `A [upos=ADP]; A -> N` under UD returns small *nonzero* counts (fixed/advmod
    attachments), so nothing fires and a meaningless number plots.

**Word-order vocabulary** — used correctly everywhere checked: "head-initial = governor
precedes dependent" (nl2grew.py:123), the signed-distance note ("head-final languages
come out negative", presets.py:228-233), "inverted" = `V << S` (docs/menzerath.md,
nl2grew examples), and the About-dialog reading guide. The single error is weak
point 5.

### Recommendations

1. **(small)** Add `without { GOV [form="__0__"] }` to `mean-distance-abs` (or correct
   its note), and purge the affected cache hashes per the rule in `cache.py`. This
   preset is producing wrong published numbers now.
2. **(small)** Rebase `sentence-length` and `tree-height` on
   `pattern { X [form="__0__"] }` (one matching per sentence → true means), or relabel
   the axes "length-weighted".
3. **(small)** Sweep UD queries to the `1=` convention: presets.py:203 (`1=case`), the
   SearchView examples, and especially "Verbs without a subject" (`1=nsubj`; consider
   mentioning `csubj`). Fix the head-initiality caption (verb-*initial* languages sit
   high).
4. **(small)** Add a scheme-difference note to `subj-obj-order` (SUD periphrastic
   clauses excluded) and a subsumption-caveat paragraph to the nl2grew SYSTEM_PROMPT
   (`obl:agent`, `aux:caus`, `acl:relcl`, `nsubj:outer` governor).
5. **(medium)** Enforce the documented rejections: unbound identifiers introduced only
   by a feature comparison or order clause in the scope should be rejected (or at
   minimum warned) instead of silently bound; `lexicon.*` should get the "clear
   message" §7 row 8 already promises; reject `e.<anything>` where `e` is an edge
   variable and the construct isn't `e1.label = e2.label`; reject singleton `-[1=*]->`
   misparse and labels matching `^[A-Z]+:` that exist in no treebank.
6. **(medium)** Add a UD differential leg — a second pytest session (grewpy's global
   config forces process separation) with `set_config("ud")` and 2-3 UD treebanks,
   covering `1=` subsumption, plain-label exactness, `det:poss`/`acl:relcl`; extend the
   SUD matrix with meta clauses, `e1.label = e2.label`, PCRE regex, `is_tree`, and a
   broad order clause that can bind `__0__`.
7. **(medium)** Decide punctuation policy for the Menzerath counters (exclude `punct`
   from `n_children`/`subtree_size` at import via backfill, or document the
   contamination in both preset notes and `docs/menzerath.md`).
8. **(small)** Document the two undocumented divergences found: POSIX-vs-Java regex
   *dialect* (row 2 covers anchoring only) and missing `textform`/`wordform` (row 10's
   "same as Grew" is not).
9. **(large)** Edge pseudo-features `e.length`/`e.delta` and the edge-span relations
   (§7 row 7) — implement via endpoint-idx arithmetic as planned, since until then the
   failure mode is a misparse rather than a clean rejection.

## 2. The typologist's report

### Strengths

- **Uncertainty is first-class and correctly chosen.** Wilson intervals instead of
  normal approximation (`backend/grugrutyp/measure.py:93-109`), no fake binomial CI on
  aggregates (`measure.py:249-259`), and the three-trigger escalation
  (`measure.py:407-435`) — especially `min_hits`, which catches the "3 hits in 50k looks
  precise" trap most published typology misses.
- **Sampling design is immune to corpus-ordering bias.** `blake2b(sent_id) % 100`
  (`backend/grugrutyp/conllu.py:204-216`) is order-independent, reproducible, shared
  across axes and across a language's treebanks, so a 2-D point describes one
  sub-corpus (`docs/sampling.md` §4).
- **Merging by summed counts, not averaged percentages** (`measure.py:283-327`) is the
  right weighting given the decision to have one point per language, and stays
  comparable with the legacy site.
- **Semantic honesty about the denominator**: the root-edge exclusion mismatch with the
  old site was found, documented with counts, and corrected in the presets
  (`docs/measures-mapping.md` §2.1) — exactly the kind of invisible 5% denominator
  shift that produces fake findings.
- **The Galton caveat is in the dialog, not a footnote**
  (`frontend/src/components/PlotStatistics.vue:97-104`), and stats verified against
  scipy (`docs/plot-statistics.md`).

### Weak points

1. **A "language" point averages registers, genres, dialects and doculects, and the
   merged value can describe no actual variety.** Measured from the live cache
   (`data/cache/measures.sqlite`, full-corpus rows): French merged 22.91% with Wilson CI
   width **0.90pt**, but per-treebank values run 19.2% (PUD) to **39.3% (FQB — a
   question bank)**, a 20pt spread; English merges Atis flight commands (99.1%) with
   learner speech ESLSpok (82.2%) and **27% of its tokens are CHILDES child-directed
   speech** (302,740 of 1.13M); French includes Poitevin
   (`SUD_French-PoitevinDIVITAL`, a distinct Oïl variety); Norwegian sums
   Bokmål+Nynorsk 50/50. *Failure scenario: a paper reports "French subject inversion =
   22.9% ± 0.5" — a corpus-composition artifact no French register exhibits, whose value
   shifts whole points whenever UD adds a treebank.*
2. **Verbatim double-counting of duplicated treebanks.** `SUD_Chinese-GSD` and
   `SUD_Chinese-GSDSimp` are the same 4,997 sentences in two scripts (identical 123,289
   tokens, identical cached counts — 80% of "Chinese" is one corpus counted twice);
   Japanese sums BCCWJ+BCCWJLUW, GSD+GSDLUW, PUD+PUDLUW — **every Japanese sentence
   counted twice under two tokenization standards** (SUW vs LUW), which differ
   systematically in token counts. *Failure scenario: Japanese's CI is √2 too narrow on
   every measure, and any segmentation-sensitive measure reports the mean of two
   incompatible analyses of the same text.*
3. **Historical stages are separate points (good) but conflated within languages and
   unflagged in the UI.** Old French, Middle French, Ancient Greek, Latin, OCS etc. are
   separate rows (`data/meta/languages.tsv:127-135`) — but "Latin" sums Perseus/CIRCSE
   (classical, 35.7/37.3% on a cached measure) with ITTB/LLCT (13th-c. scholastic /
   8th-c. charters, 51.7/52.5%): merged 50.05% ± 0.36, a clean ~15pt diachronic split
   hidden inside one dot. Ancient Greek spans Homer→Koine (Perseus 31.6% vs PTNK
   40.6%); "Sanskrit" is 99% Vedic (206,440 vs 1,843 tokens). No column, tooltip, or
   legend marks a language as historical; ~24 of 193 SUD languages are non-contemporary
   doculects, and the Latin→Old French→Middle French→French chain enters Pearson's n as
   4 independent observations. *Failure scenario: a "correlation across 190 languages,
   p < 0.001" where n is inflated by lineage chains the popup's family caveat never
   mentions.*
4. **Wilson on summed counts pretends one binomial sample; the ignored correlation is
   20–50× the reported interval.** `LanguagePoint.to_dict` (`measure.py:331`) computes
   `wilson(Σhits, Σscope)`. This ignores (a) between-treebank heterogeneity — measured
   design effects: Russian CI 0.33pt vs 21.7pt spread (Poetry 57.9% vs PUD 79.6%),
   Chinese CI 1.12pt vs 44.7pt spread — and (b) within-sentence clustering: for broad
   scopes (`pattern { GOV -> DEP }`) the effective n is sentences, not tokens, so even
   the single-treebank CI undercovers. *Failure scenario: two languages' non-overlapping
   CIs are cited as a significant difference that vanishes under any treebank-level
   random-effects model.*
5. **Deterministic sampling reuses one fixed sub-corpus forever, and escalation
   conditions on the observed sample.** The 100k budget, min_scope=30, ci_tolerance=2pt,
   min_hits=10 are individually defensible and empirically calibrated
   (`docs/sampling.md` §2), but: the same hash-selected 15% of French serves every
   measure, so a sampling fluke is perfectly reproducible and invisible (no
   between-sample variance ever surfaces); and the reported interval is a fixed-n
   interval after a data-dependent stopping rule (`measure.py:407-435`). Both are
   second-order next to point 4, but a stats reviewer will name them.
6. **`data/meta/languages.tsv` contains classifications a reviewer would flag on
   sight.**
   - **Macedonian: genus `Hellenic`** (`languages.tsv:101`) — Macedonian (mk) is South
     Slavic; outright error.
   - **Vietnamese and Thai under `Sino-Austronesian`** (`languages.tsv:171,184`) —
     Austroasiatic and Kra-Dai respectively; no macro-hypothesis covers Vietnamese
     here. The label itself (Sagart's controversial hypothesis) as a routine legend
     entry invites objections.
   - **Sign languages as Indo-European**: Spanish_Sign_Language "Romance" (`:162`),
     Swedish_Sign_Language "Germanic" (`:164`).
   - **Creoles**: Haitian_Creole → Italic (`:66`); Naija → Germanic **with area E =
     Europe** (`:115`).
   - **Amazonian misfilings**: Xavánte (Jê) and Borôro (Bororoan) as Tupian
     (`:190,:26`); Madi/jaa (Arawan) as Tupian (`:102`); Paumarí as Arawakan, not
     Arawan (`:137`) — while `appearance.tsv:18,27` styles `Arawan` and `Macro-Jê` that
     no language ever resolves to.
   - **Nahuatl ×2, K'iche', and Mayan under simple_group `South-American`/area SA**
     (`:69,:88,:188`) — Mesoamerica is not South America.
   - **Code-switching corpora as language points**: TeluguEnglish (area "I/E"),
     TurkishEnglish, TurkishGerman, Maghrebi_Arabic_French (`:103,:170,:175,:176`).
   - **`Agglutinating` is the default-view label** for Japanese, Korean, Buryat,
     Chukchi, Xibe, Yupik (family view tries `typology` first, `langconfig.py:48`),
     sitting in the legend beside genetic families and coloured identically to Turkic
     (`appearance.tsv:8-9`) — while Turkish, Hungarian, Finnish are equally
     agglutinating but untagged. Legend entries "KJ", "isolate", "Other", "unknown"
     complete the picture.
   - **Iranian is invisible**: it exists only in the dead `subgenus` column — no view
     reads it (`langconfig.py:47-54`), so Persian, Pashto, three Kurdishes and Zazaki
     label as bare "Indo-European" in the family legend while Hindi gets "Indo-Aryan".
   *Failure scenario: a reviewer screenshots the legend showing "Agglutinating" next to
   "Semitic", Vietnamese in Sino-Austronesian, and a sign language in Romance, and the
   tool's typological credibility is spent before the numbers are discussed.*
7. **Size heterogeneity is under-displayed.** 46 of 193 SUD languages rest on a single
   treebank under 2k tokens (Bengali 320, Guarani 217, Old_English 171 tokens) next to
   Czech at 4.16M; point radius is fixed at 6px (`ScatterPlot.vue:456`), error bars
   **default off** (`PlotView.vue:689`), and min_scope=30 admits points whose Wilson
   interval spans ±18pt looking identical to ±0.1pt ones. *Failure scenario: an outlier
   that drives the regression line and the "empty corner" claim is a 300-token treebank
   whose CI covers half the axis.*
8. **Per-treebank disagreement is one click too far.** The drill-down dialog
   (`PlotView.vue:517-615`) lists a language's treebanks with S / S∧Q search buttons but
   shows **no per-treebank values**, although every per-treebank `n_scope`/`n_hit` is
   already streamed to the client (`perTreebank`, `PlotView.vue:725`). The French
   19–39% spread above is currently discoverable only by running searches treebank by
   treebank. Cross-team annotation divergence (e.g. UD subtype policies) is silently
   averaged in with no exposure at all.
9. **The statistics popup slightly overclaims and omits the honest headline number.**
   The quadrant "implicational reading" (`stats.js:127-138`, threshold `max(1, 5%)` at
   `PlotStatistics.vue:141-149`) fires with ~16% per-corner false-positive probability
   at the minimum n=12 (P(Bin(12,¼)≤1)=0.158) with no exact test and no multiple-corner
   correction, yet is phrased as "the signature of a one-way implication". Missing: a
   family-aggregated correlation (one point per genus/group) or any r that survives
   Galton — the caveat tells users to check within families, but in the family view
   every IE branch is the same royalBlue triangle (`appearance.tsv:2-5`), so the
   recommended visual check is nearly impossible; also no warning that measurement noise
   in tiny languages attenuates r, nor that historical stages inflate n.

*(Synthesis note: the all-IE-royalBlue rule in point 9 is a deliberate curation
decision of Kim's from 2026-08-30 — the audit surfaces the real tension between that
rule and the popup's family-isolation advice; resolving it is a curation call, not a
bug fix.)*

### Recommendations

1. **(small)** Deduplicate re-tokenized/re-scripted treebanks at merge time: a config
   list excluding `Chinese-GSDSimp`, `Japanese-*LUW` (or preferring one variant) fixes
   provable double-counting in two languages today.
2. **(small)** Show per-treebank values in the drill-down dialog. The counts are
   already client-side; a value+CI column per treebank turns the dialog into the
   heterogeneity diagnostic the methodology needs, at near-zero cost.
3. **(small)** Fix the indefensible rows in `languages.tsv`: Macedonian→Baltoslavic;
   Vietnamese/Thai out of Sino-Austronesian; Xavánte/Borôro→Macro-Jê,
   Madi/Paumarí→Arawan (appearance rows already exist); sign languages to a `Sign`
   group; Naija area→Af; Nahuatl/Mayan out of South-American; flag or quarantine the
   four code-switch corpora. One-line TSV edits, but each is a curation decision —
   Kim signs off row by row.
4. **(small)** Add a `historical` (or `period`) column and surface it — a hollow marker
   or dagger in legend/tooltip for the ~24 non-contemporary doculects, and a one-click
   "contemporary languages only" filter feeding the stats popup.
5. **(medium)** Report a between-treebank dispersion measure on merged points — e.g. a
   random-effects (DerSimonian–Laird) interval or simply `min–max across treebanks ≥5k
   tokens` in tooltip and export next to the Wilson interval; where the spread exceeds
   the CI several-fold (French 20pt vs 0.9pt), the CI alone is actively misleading.
6. **(medium)** Add a family-aggregated correlation to the popup: r over group medians
   (one point per genus/group, n≈20–30) beside the per-language r, labelled as the
   number that survives Galton; soften the quadrant flag ("suggestive of", or a Fisher
   exact p) and note attenuation from small-corpus noise.
7. **(medium)** Default error bars on when any plotted CI is wider than ~5pt, or scale
   point radius by log n_scope — the honesty machinery exists but ships hidden.
8. **(medium)** Add a `subgenus` view / promote Iranian to genus, so the default legend
   stops presenting Persian and four Kurdish varieties as unlabelled "Indo-European"
   while naming every other IE branch.
9. **(large)** Cluster-aware intervals: per-sentence (or per-treebank-block) sufficient

   the popup currently disclaims.

## 3. The engineer's report

### Strengths

- **Failure-mode-first correctness design.** The `n_sents=0` rebuild guard
  (`scripts/import_neo4j.py:303-311`, `backend/grugrutyp/engine/neo4j_engine.py:69-76`),
  `imported_at` in the cache key (`cache.py:16-21`), the grewpy differential oracle
  suite, and up-front `validate()` before fan-out (`runner.py:283-295`) are all
  organised around the project's stated worst case: a plausible wrong number.
- **Measured, not guessed, performance engineering.** `docs/performance.md` quantifies
  the real bottleneck (150 IOPS RAID1, 44 GB hot set vs 18 GB page cache) and every
  lever — cache, per-language sampling, bounded escalation, the process-wide
  `_DB_SLOTS` cap (`runner.py:41`), smallest-first scheduling — carries its own
  measurement.
- **Statistical honesty enforced in code.** Wilson intervals, the three-trigger
  escalation policy, merge-by-summing-counts, and `refinable`/`provisional` marking are
  implemented and well tested (37 tests in `tests/test_measure.py`).
- **Security basics are right.** Every Cypher literal is a parameter, OAuth-only
  identity with no password storage, constant-time admin token compare, triple-gated
  LLM spending with per-user quotas, Neo4j bound to 127.0.0.1, `.env` at 600.
- **Documentation discipline.** Design changes land in `docs/` in the same commit,
  down to the cache-poisoning post-mortem written directly onto the schema it concerns
  (`cache.py:36-40`).

### Weak points

**Reliability**

- **No backup of anything irreplaceable.** `todo.md` Phase 4's "Neo4j backup/restore
  procedure" is open; no cron, no dump script, no off-array copy exists (verified:
  nothing in crontabs or `/etc/cron.*` touches grugrutyp). `data/cache/users.sqlite`
  (accounts, saved queries, admin/LLM flags) and `data/MANIFEST.json` (gitignored) live
  only on the same md3 array as everything else — one `rm -rf`, fs corruption, or
  double-disk failure loses all user accounts permanently and costs a multi-day
  re-import plus cache re-warm. TSVs are the only covered asset (git, pushed).
- **The service is invisible to the box's own monitoring.** `/health` returns
  `{"ok": true}` unconditionally (`main.py:138-140`) — it says nothing about Neo4j —
  and `grugrutyp-api` appears in neither `/etc/app-watchdog.conf` nor
  `/usr/local/bin/service-watchdog.sh:48-56`, which cover every other site on the
  machine; a wedged API or a dead Neo4j container goes unnoticed until a user
  complains.
- **Pre-stream failures kill the SSE stream with no error event.** In
  `main.py:425-489` the outer `try` has only a `finally`; if `select()` fails (Neo4j
  down/restarting) the exception escapes the generator after the 200 header is sent,
  and the user gets a generic network error (`PlotView.vue:1057`) instead of "the
  database is unavailable". Only failures inside the point loop produce a proper
  `error` event.
- **Neo4j down mid-run degrades slowly, not fast.** "unavailable" is classified
  transient (`runner.py:59-65`), so each treebank of each language burns 3 attempts
  with 5s/10s backoffs; a full 352-treebank fan-out against a dead DB grinds for many
  minutes producing nothing but per-point errors — no circuit breaker aborts the run
  when failures are global.
- **SQLite contention is misclassified and mislabelled.** "database is locked" matches
  none of `_is_transient`'s words (`runner.py:59-65`), so a busy `measures.sqlite`
  under the thread pool terminally fails a treebank's point — and the message claims
  "failed after 3 attempts" (`runner.py:221-223`) even when no retry happened.
- **`/measure` is unauthenticated and unthrottled.** Each request builds its own
  8-thread pool (`runner.py:310`) and pins one starlette threadpool thread for the
  stream's whole life; ~40 concurrent streams exhaust anyio's default worker pool so
  even `/health` stops answering. `_DB_SLOTS` bounds disk load but not thread/memory
  growth.
- **The import/serve race is narrowed, not closed, for `/measure`.** `select()`
  snapshots the catalogue once at run start (`runner.py:296`); an import that begins
  mid-run still yields partial counts to the live plot. They are cached under the
  superseded revision and become unreachable when the rebuild finishes — but the
  number the user is looking at right now is silently wrong. Also, `select()` runs
  twice per request (`main.py:426` and `runner.py:296`), two snapshots that can
  disagree.

**Correctness**

- **Cache-key blind spots beyond emitter semantics** (`cache.py:36-40` documents only
  the emitter): (a) the sample-bucket hash (`conllu.sample_bucket`) — change it and
  every `sample_pct<100` row silently describes a different sub-corpus; (b) property
  backfills that deliberately preserve `imported_at` (`scripts/backfill_menzerath.py`)
  — pre-backfill rows for queries touching the new properties stay reachable, exactly
  the mechanism behind the 740-row poisoning of 2026-09-02. There is no
  translator/importer version component in the key; the purge rule is a convention
  held in human memory. (`min_scope`/`ci_tolerance` are safe — they only choose which
  pct is requested — and langconfig changes are safe because merging happens at
  display time.)
- **Everything runs as root.** `/etc/systemd/system/grugrutyp-api.service` has
  `User=root`; all of `data/` including the SQLite files and WALs is root-owned;
  `admin.py:_commit` runs `git commit` as root. A FastAPI-level compromise is a root
  compromise, and it diverges from this server's own per-service-user convention.
- **Doc drift on the transaction timeout.** The container runs
  `NEO4J_db_transaction_timeout=300s` (docker inspect), while `CLAUDE.md` and the
  load-bearing comment at `scripts/import_neo4j.py:64-70` still reason from 60s.
- **`/validate` catches only `GrewSyntaxError`/`UnsupportedConstruct`**
  (`main.py:156`); a `ValueError` from `translate` surfaces as a raw 500 in an
  endpoint that exists for inline editor feedback.

**Code health**

- **`PlotView.vue` is 1,867 lines with ~74 refs/computeds and at least eight
  responsibilities**; the run and refine SSE handlers are near-duplicates
  (`PlotView.vue:1025-1061` vs `1089-1131`).
- **Duplicated merge logic frontend/backend.** `mergeProvisional`
  (`PlotView.vue:1142-1180`) re-implements `measure.merge_by_language` and applies the
  weighted-quotient rule to *every* aggregate (`:1174`) — a provisional
  `sum`/`min`/`max` aggregate briefly shows `total/n_scope` until the `done` event
  corrects it.
- **Dead code:** `Neo4jEngine._run_one` (`neo4j_engine.py:121-123`) is unused and
  broken by design. `scripts/xlsx2config.py` and `scripts/backfill_menzerath.py` are
  orphaned-by-decision but undated as such.
- **`requirements.txt` is entirely unpinned** — no versions, no lockfile; rebuilding
  `.venv` after disk loss resolves different versions than production. The frontend
  does have `package-lock.json`.

**Performance (beyond the disk story)**

- **`query_hash()` is recomputed per treebank:** `runner.py:127` calls it inside
  `_counts_at`, so one run parses and unparses both query texts up to ~705×axes times;
  it is a per-run constant.
- **Whole-language `/search` pagination is N+1 with no cache:** `main.py:284-296`
  re-runs `engine.count` for every treebank of the selection on every page turn — page
  2 of a 10-treebank language re-pays up to 10 cold counts (up to ~55s each cold).
- Indexes match the emitted Cypher (`scripts/schema.cypher` vs the generated shapes) —
  nothing new found beyond the documented hot-set problem.

**Test gaps — the five most valuable missing tests**

1. `/measure` SSE end-to-end (TestClient streaming): event sequence, `error` event on
   mid-run failure, and the pre-start failure path.
2. Runner concurrency: `_DB_SLOTS` bounds engine calls across two simultaneous
   `run()`s; closing the generator (abandoned tab) stops scheduling new languages.
3. Retry classification against real driver/SQLite error strings, including that
   terminal errors do not retry and the attempt count in the message is truthful.
4. OAuth callback flow (mocked provider) through session cookie to
   `require_user`/admin flag/LLM quota gating (401→403→429 sequence).
5. Import/serve guard: with a treebank's `n_sents` zeroed mid-test, `/search` 404s and
   `select()` excludes it — the central safety property is asserted by zero tests.

### Recommendations

1. **[small] Back up the irreplaceable files tonight.** Nightly copy of
   `users.sqlite` (via `sqlite3 .backup`), `querylog.sqlite`, and `MANIFEST.json` to
   another machine; they are megabytes.
2. **[small] Wire into existing monitoring.** Make `/health` do a cheap `RETURN 1`
   against Neo4j with a short timeout, then add the service to `/etc/app-watchdog.conf`
   and `service-watchdog.sh`.
3. **[small] Emit an SSE `error` event for pre-start failures.**
4. **[small] Put a `TRANSLATOR_VERSION` (and bucket-hash version) constant into the
   cache key** — turns the remembered purge rule into a mechanical one.
5. **[small] Pin dependencies** (pip freeze lockfile), matching the frontend.
6. **[small] Fix the small runner defects:** "locked"/"busy" in `_is_transient`, honest
   attempt counts, delete `_run_one`, hoist `query_hash()` out of `_counts_at`, single
   `select()` snapshot per request.
7. **[medium] Neo4j dump/restore procedure** (open Phase 4 item), dump shipped
   off-array; rehearse a restore once.
8. **[medium] Backstop `/measure`:** nginx `limit_req` plus a process-level cap on
   concurrent streams (429 beyond ~4) — the design already written for MCP (todo 6.7),
   brought forward to the web endpoint.
9. **[medium] Dedicated service user** and `chown`; keep root out of the request path.
10. **[medium] Write the five missing tests** — SSE and concurrency first.
11. **[medium] Split `PlotView.vue`:** extract chat sidebar, share/save, exports, and a
    single SSE-run controller; fix the provisional-aggregate merge rule while touching
    it.
12. **[large] The hot-set fix stays the right big move**, in the order
    `docs/performance.md` already ranks: RAM/SSD (calcul-server) before schema surgery.
    Nothing in this audit changes that ranking — but backups land first, because a move
    without backups is the same risk in a new place.

## 4. The security report

Scope: read-only; no secret values were read out — locations and permission modes
only.

### Strengths

- **The every-literal-is-a-parameter rule holds.** All user literals become bound
  Cypher parameters; interpolated identifiers/feature names come only from grammar
  terminals that cannot contain backticks or quotes (`grammar.lark:112-119`), cluster
  keys are regex-whitelisted then backtick-quoted (`cypher.py:42,540-562`), aggregate
  expressions compile against a closed grammar, all SQLite access is parameterised, and
  the admin git commit is an argv list with no shell and a fixed message prefix
  (`admin.py:111-114`).
- **Auth is conservative and correct where it counts:** authlib's session-bound `state`
  gives OAuth CSRF protection; the session is a signed, HttpOnly, Secure, SameSite=Lax
  cookie holding only the uid, cleared on login (`auth.py:141-143`); the admin token
  compare is constant-time (`admin.py:77`); `/me/queries` reads and deletes are
  strictly user-scoped in SQL (`users.py:141-169`) — no IDOR.
- **The LLM human-approval claim verifies end to end:** every model proposal passes the
  same parse/validate/combine pipeline as hand-typed queries plus a feature-existence
  gate (`nl2grew.py:218-242`), replies and proposals render exclusively through Vue
  text interpolation — zero `v-html`/`innerHTML` in the whole frontend — and only the
  user-clicked "load & plot" button executes anything; spend is triple-gated.
- **Minimal network exposure:** uvicorn and both Neo4j ports bind 127.0.0.1 only
  (verified via `ss` and `docker ps`); the vhost is TLS-only with HTTP→HTTPS redirect;
  `.env` is root-owned mode 600 and git-ignored.
- **Privacy by design in the app layer:** the query log stores no
  IP/user-agent/user id, share links keep state in the URL fragment, uvicorn's access
  log only ever sees 127.0.0.1, and log rows are pruned after 180 days.

### Weak points

1. **Unauthenticated, unmetered access to the most expensive operation — HIGH.**
   `/measure` is public, `token_budget: 0` explicitly means "no sampling at all"
   (`main.py:352-355`), and there is no `limit_req`/`limit_conn` anywhere in
   `/etc/nginx/` and no rate limiting in the app. Attack: an anonymous curl loop
   posting exact-mode `/measure` requests (55s cold per treebank query, 705 treebanks,
   spinning disks already the bottleneck) pins the RAID at 100% and takes down
   grugrutyp *and* the legacy Django site sharing the box.
2. **Unbounded query text into an Earley parser, behind a 75MB body limit — HIGH.**
   `SearchRequest.request` (`main.py:91`), `ValidateRequest.request`
   (`main.py:122-123`) and `AxisSpec.scope/response` (`main.py:327-328`) have no
   `max_length`, while the server-wide `client_max_body_size 75M` applies to
   `/grugrutyp/api/`. Attack: one unauthenticated POST to `/validate` with a
   multi-megabyte pattern buys minutes of CPU (lark Earley is super-linear) per
   request; the full text is also written into the query log.
3. **API service runs as root with zero sandboxing — HIGH (impact), low likelihood.**
   `User=root`; `NoNewPrivileges=no`, `ProtectSystem=no`, `ProtectHome=no`. Any RCE in
   the FastAPI/pydantic-core/neo4j-driver stack parsing untrusted input becomes
   instant full-box compromise, including the legacy sites and all secrets.
4. **SSE/threadpool exhaustion — MEDIUM.** `/measure` is a sync generator inside
   `StreamingResponse`; each anonymous stream occupies an AnyIO threadpool thread
   (default capacity ~40) for the entire multi-minute run. ~40 concurrent idle-reading
   SSE clients starve every other endpoint, including `/health` and admin.
5. **World-readable user and log databases — MEDIUM.** `users.sqlite`,
   `querylog.sqlite`, `measures.sqlite` (+WAL/SHM) are mode 644 root-owned in a 755
   tree. Any local Unix account on this shared box reads every user's email/name and
   the full query log.
6. **No security headers, and a permanent admin credential in localStorage — MEDIUM.**
   nginx sends no HSTS, CSP, `X-Frame-Options` or `X-Content-Type-Options`; the admin
   token sits unexpiring in localStorage and rides every admin call. Any single future
   XSS (there is none today) exfiltrates a break-glass credential that stays valid
   until someone edits `.env`; no CSP exists as a second layer.
7. **TSV/format injection in admin config writes — LOW.** `_upsert`/`_write_rows`
   (`admin.py:100-103,122-170`) join values with `\t`/`\n` without rejecting embedded
   tabs or newlines. An admin pasting a value containing a tab silently corrupts
   `languages.tsv` column structure; integrity only, admin-only.
8. **`/docs`, `/redoc`, `/openapi.json` publicly reachable — LOW.** FastAPI defaults
   not disabled; hands an attacker the complete schema for the DoS vectors above.
9. **Dependency pinning absent server-side — LOW.** `requirements.txt` pins nothing.
   Currently installed versions are recent and clean (authlib 1.8.0, httpx 0.28.1,
   itsdangerous 2.2.0, fastapi 0.141.1, uvicorn 0.52.4, chart.js ^4.5.1 — nothing
   known-vulnerable flagged). The next `pip install -r` pulls whatever is newest.
10. **The privacy promise does not extend to the nginx layer — LOW (observation).**
    `/var/log/nginx/access.log` records client IPs + endpoint paths, rotated daily,
    kept 14 days. Query text does stay out — but "no IPs anywhere" is only true above
    nginx.

Non-findings worth recording: session fixation not applicable (signed cookie, cleared
and rewritten at login); no non-admin path into `/admin/*`; CORS is dev-origins-only
without credentials; prompt injection cannot execute anything — though note that
"load & plot" runs the proposal immediately (load and run are one act, not two).

### Recommendations

1. **[small]** `max_length` (~10,000) on all query-text fields;
   `client_max_body_size 1m;` inside the `/grugrutyp/api/` location.
2. **[small]** nginx `limit_req` (per-IP) on `/grugrutyp/api/`, stricter zone +
   `limit_conn` (2-3 per IP) on `/measure`.
3. **[small]** Dedicated service user + `NoNewPrivileges=yes`, `ProtectSystem=strict`,
   `ReadWritePaths=`, `ProtectHome=tmpfs`.
4. **[small]** Require a signed-in user (or clamp) when `token_budget` is null/0;
   anonymous requests get the default sampling budget.
5. **[small]** `chmod 640` the three SQLite files (+WAL/SHM), `chmod 750 data/cache/`.
6. **[small]** HSTS, `X-Content-Type-Options`, `X-Frame-Options` at the vhost;
   **[medium]** author a real CSP for the SPA.
7. **[small]** Pin the backend (pip freeze lock).
8. **[medium]** Cap concurrent `/measure` streams in-app (global semaphore → 429).
9. **[small]** Reject `\t`/`\n`/`\r` in admin TSV values via pydantic validators.
10. **[small]** `docs_url=None, redoc_url=None, openapi_url=None` (or admin-gate them).
11. **[medium]** Retire the localStorage token path for routine admin use; keep the
    `.env` token as break-glass only, rotate it after bootstrap.
12. **[small]** If the no-IP promise should be end-to-end: shorten nginx retention for
    this vhost or switch to an IP-anonymised `log_format`.
